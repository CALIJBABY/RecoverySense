# RecoverySense ML Framework

This package contains two linked but separate machine-learning pipelines:

1. A craving-risk model that uses smartwatch windows, EMA history, and eligible prior-night sleep summaries to estimate when an EMA should be triggered.
2. A binary sleep/wake model trained from directly collected overnight watch signals and user-confirmed sleep intervals.

## Included capabilities

- Sensor schema validation, range checks, resampling, interpolation, and filtering
- 30-second craving windows with 15-second overlap
- Non-overlapping 30-second sleep epochs
- Heart-rate, accelerometer, gyroscope, step, off-body, quality, participant-local time, and interaction features
- Prior EMA context
- Participant-local cyclic time features using recorded timezone offset metadata; missing local-time metadata stays missing rather than being treated as UTC routine time
- Leakage-safe prior sleep context with 36-hour current and 48-hour maximum-age rules
- Participant-grouped train/test splitting and grouped cross-validation
- Decision Tree, Logistic Regression, SVM, Random Forest, Gradient Boosting, and Naive Bayes comparisons for craving risk
- Decision Tree, Random Forest, Gradient Boosting, and Logistic Regression comparisons for sleep/wake
- Temporal smoothing for sleep/wake output
- Feature-group ablation, including whether sleep context adds value
- Firestore export for sensor, EMA, and sleep-session CSV files
- Saved model bundles, metrics, predictions, and automated tests

## Important limitation

Synthetic demo data can be generated by the included generator only to verify that the software runs. Generated demo CSV/model/report artifacts are intentionally not shipped in the release tree. They do not establish craving detection, relapse reduction, sleep-stage accuracy, or clinical effectiveness. The initial sleep labels are user-confirmed onset and wake times. EEG or polysomnography labels are needed before claiming Wake/N1/N2/N3/REM staging.

## Quick start

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".\ml[dev]"
recoverysense-ml --config ml/config/default.yaml run-demo
pytest ml/tests
```

## Real Firestore data

```powershell
recoverysense-ml --config ml/config/default.yaml export-firestore --credentials path\to\service-account.json
recoverysense-ml --config ml/config/default.yaml build-dataset
recoverysense-ml --config ml/config/default.yaml train
recoverysense-ml --config ml/config/default.yaml build-sleep-dataset
recoverysense-ml --config ml/config/default.yaml train-sleep
recoverysense-ml --config ml/config/default.yaml ablation
```

See `docs/ML_FRAMEWORK_GUIDE.md` and `docs/SLEEP_TRACKING_AND_MODEL.md`.

## Raw PPG support

When raw PPG has been uploaded, Firestore export creates:

```text
ml/data/raw/raw_ppg.csv
```

The craving and sleep dataset builders automatically align those samples to their model windows. Features are produced by `recoverysense_ml.ppg`. Pulse intervals are labeled PRV rather than ECG-derived HRV, and Samsung status `-1` samples are retained in raw storage but excluded from signal processing.
